# AI usage report

## Tool used

OpenAI Codex assisted with planning and implementing this portfolio. The work was based on the supplied bootcamp assignment and resume, with the user's instruction to use real details and placeholders for project links.

## Tasks where AI helped

- Extracted requirements from the assignment and content from the resume.
- Proposed the page structure and visual direction.
- Generated the HTML, CSS, JavaScript, CSS illustrations, and SVG favicon.
- Implemented responsive layouts, theme persistence, greeting logic, a welcome interaction, and contact-form validation.
- Created browser interaction checks, captured screenshots, and reviewed them.
- Drafted the README and this report, and recorded incremental implementation commits.

## Representative prompts

These are actual user instructions from the session:

- “first see this and lets get to a plan and then proceed” — supplied with the assignment document.
- “use real details,is github connected?u need to create a new git public repo and then we can start”
- “I will just share my resume” — supplied with the resume PDF.
- “use placeholders for links”

The user subsequently agreed to proceed. There was no separate detailed prompt specifying every CSS rule or function; Codex made those implementation choices from the agreed plan.

## Generated code retained and modified

The current HTML, CSS, JavaScript, and favicon were generated by Codex and retained in the implementation. Content was drawn from the resume and condensed for the portfolio. This report does not imply that the user has reviewed or independently approved every generated line.

- Retained semantic sections, responsive Grid/Flexbox layouts, CSS theme variables, event listeners, and field-validation functions.
- Used noninteractive project-link labels as requested, rather than invented destinations.
- Included explicit demo-only feedback so form validation cannot be mistaken for email delivery.
- Kept decorative project illustrations hidden from assistive technology; the adjacent text describes each project.
- Formatted the generated files for readability.

## Issues and corrections

- The first CSS draft contained an unnecessary empty `@import` rule. It was removed before browser verification.
- The initial assignment extraction hit a terminal encoding error; extraction was repeated with UTF-8 output to read the remaining requirements.
- The browser launcher initially failed within the execution sandbox. It was rerun with the required execution permission; this was an environment restriction, not a website defect.
- No additional functional defects were reported by the completed browser checks. This is not a claim that all browsers or accessibility scenarios were tested.

## Verification performed

Codex ran `node --check js/script.js` and an automated Playwright flow against the site in installed Microsoft Edge. Checks covered all greeting branches, welcome feedback, theme switching and reload persistence, section navigation, invalid and valid form input, repeated submission, stale-success clearing, the keyboard skip link, and a no-JavaScript fallback.

Responsive overflow checks covered widths from 320px to 1440px, including both themes. No browser JavaScript or console errors were observed during the tested flow. Desktop light, desktop dark, and mobile screenshots were captured and visually inspected.

Playwright and Prettier were used only as local development tools. Neither is loaded by the submitted website, which uses only HTML, CSS, and vanilla JavaScript.

The user should still review the published content and complete the manual checklist in the README, especially on their own browser and device. Project benchmark figures were taken from the resume and were not independently retested.
